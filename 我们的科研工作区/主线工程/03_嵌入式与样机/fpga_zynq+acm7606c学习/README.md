
学习方式固定为：**先讲原理 → 看现有例程 → 你解释关键逻辑 → 仿真 → 下载与测量 → 记录通过项。** 每轮推进一小步，不要求你读完1693页教程。

### 3.1 已定位的适配点，不把它们说成原工程全部有问题

1. PWM的`pwm_gen.xpr`实际器件是`xc7z015clg485-2`，尽管某些源码注释写7020。`pwm_gen_test_pin.xdc`使用L5/R4/R2，不是本板已经核对的U18/T19/T10。教程第409页也明确注明本章为7015蜂鸣器参考内容，不能直接在BX71实现该演示；不代表PWM原理不能移植。文件夹名、注释、实际工程配置必须分开检查。
2. PWM顶层是蜂鸣器演示，通过音符切换频率，不是三端口控制程序。测试平台则包含50 kHz/100 kHz及不同占空比激励，适合先学仿真。
3. `pwm_gen.v`中，`pwm_gen_en`只控制计数器；输出比较没有直接受它封锁。当CCR≥ARR等边界参数出现时，使能为0不能保证输出为低。输出复位为低与可靠停机封锁是两件事。这里只做静态代码分析，尚未运行仿真验证。
4. 该PWM模块直接使用输入ARR/CCR，没有周期边界影子更新；没有三端口合法状态管理和故障锁存。教学例程可以解释PWM，功率控制还需补齐这些机制。
5. 两份7606C工程都配置为`xc7z020clg400-2`，但ADC约束中例如CONVST=J14、BUSY=E17；本目录BX71的GPIO0接线表则是CONVST=K14、BUSY=F16。故必须按实际插座/线缆逐线核对，不能把这两份XDC当作本板直插接线已通过。
6. 一份7606C驱动内部用`Speed_Set`计数自行产生`trig`，不是已经由PWM触发的控制采样。后续要把采样相位与PWM统一安排，不能各自自由运行后直接拼闭环。
7. 该7606C驱动设置`ad7606_os_o=0`，按BUSY下降握手读取8路，并在末尾输出`Conv_Done`；还存在每轮末尾拉高RESET的流程。要对照具体芯片模式与手册核定复位脉宽、滤波带宽和寄存器保持行为，不把“文件名含C”当作100 kHz控制链已验收。
8. 教程第60、88页建立工程的文字举例选择7010，而提供的LED工程为7020；你的板子选7020，不能机械照抄截图。教程第88页端口表写LED低有效，但第59页电路图、用户手册及LED例程支持高有效；以实际电路核对。

### 5.3 实际例程只有一条核心逻辑

```verilog
assign led = 1;
```

意思是让逻辑输出`led`持续为高，相当于电路把这个输出连到逻辑1；不需要`while(1)`反复执行。这不是闪烁程序，也不需要时钟。

对应XDC：

```tcl
set_property PACKAGE_PIN T10 [get_ports led]
set_property IOSTANDARD LVCMOS33 [get_ports led]
```

两行分别表示：`led`绑定封装脚T10；按3.3 V LVCMOS标准使用。这里的电平设置必须与对应IO Bank的实际供电匹配，不能靠软件把1.8 V供电变成3.3 V。

在MCU上，GPIO外设本来就存在，你通过寄存器配置它；在FPGA上，我们先描述输出电路，再用约束把它接到物理脚。

### 5.5 提前知道下一步的一个计算

以50 MHz时钟、向上计数0～499为例：

\[
T_{\mathrm{clk}}=20\,\mathrm{ns},\qquad
f_{\mathrm{PWM}}=\frac{50\,\mathrm{MHz}}{500}=100\,\mathrm{kHz}.
\]

若比较条件是`cnt < 200`，每周期500拍里高电平200拍，占空比40%。这个定义下周期寄存器若存“最大计数值”应为499；厂商例程则从ARR向下计到1，ARR存500表示500拍，不能混用两种定义。边沿对齐时此时占空比步长1/500=0.2%。需要更细分辨率时再学习时钟向导，不先加多时钟复杂度。

### 8.1 三路引脚选择

|---|---|---|---|
| `pwm1` | GPIO1_28 | Y14 | 33 |
| `pwm2` | GPIO1_29 | W15 | 34 |
| `pwm3` | GPIO1_30 | W13 | 35 |

核对来源：用户手册PDF第27页图40及第28页引脚表；`BX71开发板管脚信息表.xlsx`的Sheet1第76～78行；`ACM7606接BX71管脚信息表.xlsx`的两套ADC接线。已逐项检查Y14/W15/W13不在该ADC表列出的信号脚集合中。该表名不含C，实际C模块的完整引脚、跳线和扩展功能仍须按实物/模块资料核定；这次排针选择并不代表C模块接线已验收。

### 8.2 先用MCU定时器理解

在MCU上，一只定时器的三个比较通道可以共享同一个CNT/ARR，CCR1/2/3决定三路脉宽。在FPGA里我们描述同样的电路：一个公共计数器加三个比较器。

```text
50 MHz时钟 → 0～499循环计数器 ┬→ 与100比较 → PWM1
                            ├→ 与200比较 → PWM2
                            └→ 与300比较 → PWM3
```

选择向上计数0～499，恰好500拍：

\[
f_{\mathrm{PWM}}=\frac{50\times10^6}{500}=100\times10^3\,\mathrm{Hz},
\quad T_{\mathrm{PWM}}=10\,\mu\mathrm{s},
\quad D_k=\frac{C_k}{500}.
\]

其中C是比较阈值，采用`cnt < C`。三路示例分别高100/200/300拍，即20%/40%/60%，高电平时长2/4/6 μs；周期相同，边沿对齐。它们是独立脉宽的学习用波形，不是任何三端口模式的现成门极命令。

用C语法表达判断逻辑：

```c
/* 仅用于理解比较关系，不是在CPU中执行的20 ns中断程序 */
pwm1 = (cnt < 100);
pwm2 = (cnt < 200);
pwm3 = (cnt < 300);
```

FPGA里这三个比较器同时工作，不存在CPU先算完PWM1才轮到PWM2。核心概念可写成：

```verilog
assign pwm1 = (cnt < 9'd100);
assign pwm2 = (cnt < 9'd200);
assign pwm3 = (cnt < 9'd300);
```

`assign`描述持续存在的比较逻辑；`9'd100`表示9位宽的十进制100。计数范围0～499需要9位，因为2^8=256不够、2^9=512足够。这里暂省完整模块、计数器、启动/复位与使能封锁，不能直接当完整可下载功率控制程序。

2. 能解释50 MHz为什么计500拍就是100 kHz，为什么从0开始数要到499。
3. 能计算40%对应阈值200，而不是把频率100 kHz写成比较值。

## 9. 独立ADC验证与后续组装规划（2026-10-30）

### 9.1 先分清采集与反馈控制

完整链路：传感器调理电压 → ADC原始码 → 通道对应/标定/工程量 → PI或NN控制器 → 占空比命令 → PWM → 功率电路 → 新一轮采样。

ADC负责测量，不负责决定占空比。反馈是把测到的状态交给控制器并影响下一轮PWM的连接关系，不需要再发明一个“采集反馈算法”。NN-EMPC指训练好的网络近似EMPC控制律；初版板上运行网络推理，不再串一个在线EMPC求解器。MATLAB的EMPC保留作离线教师与比较基准。

### 9.2 推荐推进次序与验收

| 步骤 | 做什么 | 验收后再往下走 |
|---|---|---|
| 1 独立ADC | 先学CONVST启动、BUSY握手、CS/RD读数；八通道读成一帧，先看低压输入的原始码 | 通道次序、符号、零点/多点读数正确；整帧更新；BUSY超时、重复触发有明确处理 |
| 2 工程量与PWM同步 | 原始码转ADC脚电压，再按传感器比例/偏置转A和V；接PWM统一触发，暂保留固定占空比 | 采样相位稳定；帧号不乱、无新旧通道混帧；实测转换至整帧齐备延迟；数据能观察导出 |
| 3 可调PWM与PI基线 | PWM增加运行时占空比输入、整组影子锁存和周期边界更新；先用测试命令验证，再做PI离线对拍 | 0/中间值/100%或模式允许范围、限幅、超时与停机行为明确；先只做Vs→Vo |

| 6 五模式与切换 | 再扩展另两种SISO、SIDO、DISO及功率级切换 | 每模式控制量、辅助占空比、网络输出含义与切换状态管理分别通过 |

### 9.4 我们实际要几个量

本轮核对`48_72_120_C220_16_8/EMPC_LOOP/SU_SISO_Vs48_Vo120/code/private/tpc_add_relu_block.m`：外部输入是`iL、Vo、instantaneous load current、Vref`。

| 网络外部量 | 来源 |
|---|---|
| iL | 电感电流传感器，ADC通道 |
| Vo | 被控输出电压采样，ADC通道 |
| Io | 负载电流传感器，ADC通道；不能因使用电子负载就默认知道实际瞬时电流 |
| Vref | 程序中的参考给定，不占ADC通道 |

因此先按三路物理反馈规划，不将四个网络输入说成四个ADC采样，也不在变负载条件下直接用固定R估算Io。额外通道可预留Vs、VB及保护/其他模式需求，最终按电路与相应网络逐一确认。

预处理还要核实际MAT中的`rawInputTransform`：若为`reference_current`，第三特征先变成`Io*Vref/max(Vo,1e-6)`，再进行`inputGain/inputShift`。并非仅把三路ADC码直接塞入乘加器。后续只读导入已有模型，不重新训练。

### 9.5 组装前必须补的接口

现有PWM函数以编译期常量决定脉宽，并未提供控制器可写的占空比寄存器。ADC即使正确读数，直接接到当前工程也不会形成闭环。需要：每周期成组接收控制命令、检查模式允许范围、锁存后在边界更新，以及控制命令缺失/超时的处理。

计划采用清晰的一周期调度：周期k指定相位采样，读取/换算/控制运算完成后提交命令，于约定的后续周期边界生效。100kHz下总周期为10μs，50MHz下相当于500拍；实际可用计算时间还要扣除采样相位、转换、并行读取和更新裕量。先量/算总延迟，再核它与仿真控制延迟假设一致，不先宣称能在当周期即时反馈。

### 9.8 ADC第一课：如何使用已有驱动（2026-10-31）

本轮回到主线，实际检查`D:/Project/fpga_project`：五模式PWM工程与验证记录仍在，独立ADC工程尚未创建。接下来先理解已有驱动的用户接口，再写验证顶层。

| 端口 | 类比C/MCU | 含义 |
|---|---|---|
| Clk | 外设工作时钟 | 本例程100MHz，用于走状态机，每拍10ns，不是采样频率 |
| Reset_n | 初始化/复位 | 低有效，后续顶层需在时钟稳定后释放 |
| Go | ADC采集使能 | 高时允许开始新一轮，低时完成已经开始的一轮后停止 |
| Speed_Set | 定时器周期值 | 内部计数0至此值；100MHz与999对应100kHz触发目标，仍需确认驱动来得及完成 |
| data1～data8 | 八个结果寄存器 | 逐路更新的原始16位码，尚未换算实际电压/电流 |
| Conv_Done | 一帧完成事件 | 八路读完后高一拍，用于统一锁存同批数据 |

独立测试的用户侧关系为：100MHz+复位送驱动，Go控制启动，Speed_Set设置触发间隔；模块外侧的CONVST/BUSY/CS/RD/DB由驱动处理；data1～data8在Conv_Done有效时统一复制到帧寄存器并产生frame_valid，ILA观察这些帧寄存器。先不接任何调压算法。

概念性C类比（不用于直接运行或生成RTL）：

```c
if (adc_frame_done) {
    frame.ch1 = adc_ch1;
    frame.ch2 = adc_ch2;
    // ...复制至ch8，同一批数据统一交给后续模块
    frame.valid = true;
}
```

不能让控制器在通道1刚更新、通道8仍是上一帧时开始计算。原data1～data8逐路更新，统一帧发布是验证顶层的职责。采样是同一批同时采样，读出是复用16位总线分八次完成。

首轮先验证CH1已知低压输入：观察CONVST、BUSY、RD、Conv_Done与CH1原始码，再检查八路通道标识和整帧一致性。量程和二补码解释随后对照模块设置讲解。固定输入读数正确后，才做工程量换算、同步触发和与PWM组装。本轮仅教学与进度核对，未生成或下载ADC工程。

### 9.10 完整数据导出与MATLAB用途（2026-11-02规划）
