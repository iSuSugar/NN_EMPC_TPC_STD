本目录为轻量化工程：`D:\Project\NN_EMPC_TPC\48_72_120_C220_16_8`。64→32基准仍在旁边的`48_72_120_C220`，不在这里覆盖或混用。

## 本轮做什么

只修改五个独立模式parameters中的`cfg.hiddenSizes = [16; 8]`，重新训练网络，然后运行五个独立模式和四类切换的实际开关电路验证。电路参数、初始化、辨识模型、EMPC教师、标签及训练数据保留。

辨识、EMPC、采样与整理已有，不需重跑`model_calculate → EMPC1 → train_sample → zhenghe`。只缩小网络时从`myguiyihua`开始。

五个模式各自一次主流程训练，使用原脚本的分组划分、归一化、初始化和训练规则；不是把48→120 V实验的18次多结构/多种子比较自动扩展到了其余模式。训练目标1e-8与稳压验收分开报告。

修改前的参数、训练网络、电路和结果已备份，位置见`validation/nn16_8_preparation.json`。本轮进度看`validation/nn16_8_status.json`，不要把复制过来的旧64→32验收记录当成16→8结论。

## 1. 先做五个独立模式

每个模式进入自己的code目录，检查parameters中hiddenSizes为16、8，然后：

```matlab

report = run_closed_loop;    % 用新网络重新运行电路
```

| 模式 | EMPC_LOOP下的目录 | 网络输出数 |
|---|---|---:|
| 48 V电源→72 V电池 | SU_SISO_VS48_VB72 | 1 |
| 48 V电源→120 V负载 | SU_SISO_VS48_Vo120 | 1 |
| 72 V电池→120 V负载 | SU_SISO_VB72_Vo120 | 1 |

| 电源、电池共同给负载供能 | SU_DISO_VS48_VB72_Vo120 | 2 |

例如：


每个模式的主要文件：

* `models/net_48_72_120.mat`：本模式实际网络；同名文件放在不同模式目录，不能互相覆盖。
* `results/NN_validation.json`：训练/测试误差和hiddenCounts。
* `results/native_switching_dynamic.json`：独立模式电路结果；本轮另记nnArchitecture和实际网络路径。
* `results/NN_native_trajectory.json`：真实轨迹上的网络与EMPC查询误差。

核对实际网络规模，而不只看参数文件：


## 2. 再做四类切换

**切换目录没有一套独立训练的新网络。先训练组成模式，切换时读取它们的网络。** 四类切换的SISO指48 V电源→120 V负载，不是72 V电池→120 V，也不是48→72 V。

| 切换过程 | code目录 | 实际复用的独立模式网络 |
|---|---|---|
| SISO→SIDO→SISO | SU_SISO_SIDO_SISO_120/code | SISO_VS_VO、SIDO |
| SIDO→SISO→SIDO | SU_SIDO_SISO_SIDO_120/code | SISO_VS_VO、SIDO |
| DISO→SISO→DISO | SU_DISO_SISO_DISO_120/code | DISO的两个输出头、SISO_VS_VO |
| DISO→SIDO→DISO | SU_DISO_SIDO_DISO_120/code | DISO的两个输出头、SIDO |

进入一个切换目录后，直接运行：

```matlab
report = run_closed_loop;
```

例如：

```matlab
cd('D:\Project\NN_EMPC_TPC\48_72_120_C220_16_8\EMPC_LOOP\SU_DISO_SIDO_DISO_120\code');
report = run_closed_loop;
```

这里不需要重新辨识、重新生成切换标签或再训练一个“切换网络”。切换目录里的myguiyihua只是检查/复用组成模式的训练产物；网络文件已存在时，它不会自动重新训练，因此不能把运行它当作完成了16→8训练。

## 3. 切换程序实际做了哪些事

1. 读取本切换目录parameters中的`cfg.mapping`。
2. 用本工程索引找到组成模式，读取它们的`models/net_48_72_120.mat`。
3. 检查实际网络为本轮16→8；DISO按head=1、head=2分别取两个控制输出。两个头来自同一份DISO网络。
4. 从本切换目录的circuit/template复制原切换功率电路，设置相同L/C和负载，接入网络及原PWM逻辑。
5. 原电路的Step与辅助开关调度在规定时刻改变有效工作通路。电感电流、电容电压连续演化，控制器对应原模式通道。
6. 仿真后检查三个模式平台的电压、端口功率方向和两次事件，而不是仅看最终120 V。

cfg.mapping每项含三个字段：

| 字段 | 含义 |
|---|---|
| mode | 从哪个独立模式加载网络，例如DISO或SIDO |
| head | 使用该网络第几个输出，DISO有1和2 |
| pwm | 接入原电路中的哪个PWM块；应按映射查，不按名字猜MOSFET编号 |

网络可能并行计算，真正的模式通路还受原开关调度控制。这里验证的是预定时序下的切换，不是已经实现了硬件自动判断模式的状态机。

## 4. 时间轴为什么与Step参数看起来不一样

当前四类切换先有0.25 s初始化；反馈后在50、70 ms发生切换。因此实际仿真Step可能显示0.30、0.32 s，而结果图把初始化去掉，从反馈接管时刻计时，显示50、70 ms。应同时看`initializationSeconds`和事件时刻。

## 5. 运行后看什么

* `report.allPlateausRegulated`：三个平台是否都满足声明稳压带，不能只看finalMeanVoltage。
* `report.events`：两次切换的电压偏差和恢复时间。
* `report.ports.requestedPowerDirectionConfirmed`：SIDO/DISO/SISO各段的端口方向是否符合模式。
* `report.networkSources`：每个PWM映射实际读取的网络文件、mode、head、hidden和网络指纹。本轮应全部指向16_8工程，hidden都为[16,8]。
* `show_results`：只查看已保存的闭环总览、变化处放大两张图，不重新仿真。

本轮记录保留原定义：启动峰值单独报告，不作为老师指定的稳态门槛。16→8电压稳住也不表示训练已达到1e-8，或已完成定点、延迟及硬件验证。
